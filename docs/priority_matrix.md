## 優先度分類

### 必須機能（MVP）- 合計 6.5人日

これがないとマルチエンディングシステムが成立しない機能。

| 機能 | 説明 | 工数 |
|------|------|------|
| エンディング判定ロジック更新 | 好感度×スコアで12種類に分岐 | 0.5日 |
| endings.ts 定数ファイル | 12種類のエンディングデータ定義 | 1.0日 |
| EndingScene コンポーネント | エンディング演出用の再利用可能コンポーネント | 1.5日 |
| ending.tsx 画面更新 | 新エンディングシステムに対応 | 1.0日 |
| シナリオテキスト執筆 | 12種類 × 約10-20ステップ | 2.5日 |

### 推奨機能 - 合計 3.0人日

ユーザー体験を大幅に向上させる機能。

| 機能 | 説明 | 工数 |
|------|------|------|
| エンディングギャラリー | 達成したエンディングの一覧表示 | 1.0日 |
| 好感度可視化 | ハートアイコンで現在の好感度を表示 | 0.5日 |
| エンディングヒント | 未達成エンディングの条件ヒント | 0.5日 |
| スキップ機能強化 | 既読テキストのスキップ | 1.0日 |

### オプション機能 - 将来追加検討

予算・時間に余裕があれば追加。

| 機能 | 説明 | 工数 |
|------|------|------|

| ボイス対応 | キャラクターボイス追加 | 5.0日+ |
| BGM切り替え | エンディング別の専用BGM | 1.0日 |

## 実装順序

```
Phase 1: 基盤（必須）
├── 1.1 endings.ts 定数ファイル作成
├── 1.2 エンディング判定ロジック更新
└── 1.3 EndingScene コンポーネント実装

Phase 2: シナリオ（必須）
├── 2.1 BAD END シナリオ（2種）
├── 2.2 NORMAL END シナリオ（5種）
├── 2.3 GOOD END シナリオ（5種）
└── 2.4 TRUE END シナリオ（1種）

Phase 3: 画面更新（必須）
├── 3.1 ending.tsx リファクタリング
└── 3.2 テスト・デバッグ

Phase 4: UX改善（推奨）
├── 4.1 好感度可視化
├── 4.2 エンディングギャラリー
└── 4.3 スキップ機能強化
```
